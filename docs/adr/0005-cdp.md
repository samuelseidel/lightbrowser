# ADR 0005: CDP as the control API for both families

Status: Accepted (2026-11-02)

## Context

Our users already drive browsers with stock Playwright and Puppeteer. We want
tests to run against LightBrowser with no custom client. Playwright can attach
to any browser that speaks the Chrome DevTools Protocol (CDP) through
`connectOverCDP`, and Puppeteer does the same through `connect`.

The Firefox family also needs a control API. Playwright's own Firefox support
uses a patched Firefox with the Juggler protocol, and it is not a protocol
Playwright exposes for third-party servers. WebDriver BiDi exists, but
Playwright does not use it for connecting to arbitrary browsers.

Control must not leave tells in the page. Playwright's injected script has to
run in an isolated world, and nothing may be installed in the page's main world.
A persona is only believable if the page cannot see the automation.

## Decision

LightBrowser exposes one control protocol: a CDP server over WebSocket
(`lb-cdp`, using `tokio-tungstenite`). It is used by both the Chrome and the
Firefox builds.

- A Firefox-family LightBrowser still speaks CDP. The persona decides what the
  page sees. The control protocol is separate from the fingerprint and is never
  visible to page scripts.
- We implement the domains Playwright needs: Browser, Target, Page, Runtime,
  DOM, Input, Network, Fetch, Emulation, Accessibility (list in
  ARCHITECTURE.md).
- We add a custom `LightBrowser.*` domain for `setPersona`, `humanClick`,
  `humanType`, `humanScroll` and `fingerprintReport`.
- `Emulation.*` calls are checked against the persona. A call that would make
  the persona inconsistent (for example a UA override that contradicts the
  family) is rejected.
- A Playwright `BrowserContext` maps to a LightBrowser context with its own
  persona, cookie jar, storage and cache partition.
- The Python SDK is a thin layer over Playwright `connect_over_cdp`.

## Alternatives considered

- **Juggler.** It is Firefox-specific, undocumented as a stable protocol, and
  tied to Playwright's patched Firefox. Stock clients can't connect to it.
- **WebDriver BiDi.** A standard, but the stock Playwright and Puppeteer
  workflows we care about don't connect to arbitrary servers over BiDi, and
  its coverage of what Playwright needs (isolated worlds, Fetch interception,
  AX tree) is narrower. We could add it later as a second transport.
- **Our own protocol (GPHT/ShadowChannel).** Fine for GeckoPhantom, where
  the browser and SDK ship together. Here it would require a custom client for
  every language and lose the stock Playwright and Puppeteer ecosystem.
- **WebDriver classic.** Request/response only, with weak event support and
  poor fit for Playwright.

## Consequences

- Existing Playwright and Puppeteer scripts work unchanged, for Chrome and
  Firefox personas alike.
- We must implement and keep up with the CDP surface Playwright uses. CDP is
  large and changes, so we implement only what is needed, test it against
  Playwright (M3), and return clear errors for the rest.
- A Firefox-persona LightBrowser speaks a Chromium protocol. This is fine for
  validation, but we should not claim our CDP behavior mirrors real Firefox.
- Our Python SDK stays small, since Playwright does the heavy lifting.
- ShadowChannel and the binary mmap config from stealth-browser are not needed,
  because everything runs in one process.
- The CDP server and isolated-world handling are security-sensitive and must
  not leak into the page world.
